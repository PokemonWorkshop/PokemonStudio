# Event flows

These flows describe how users move through the interface to work with their events.

## Reach and open an event

> 🚧 **Navigation between maps and events is still being explored.**

Users reach an event through its map, or through the list of all events.

On a map, events appear on their tiles and are listed in the map's floating panel. Selecting an event in this panel also selects it on the map.

Opening an event, on the map or in its panel, moves the whole screen from the map to the event. The sidebar turns to the event's map, with information such as its name and the list of its events. The [Event Builder](event-builder/README.md) replaces the map, and the floating panel now describes the event.

### List of all events

This list gathers all the events of the project, regardless of the map they are placed on. Opening an event from this list leads to the same view as opening it from its map. Users can search the list by name, and filter it.

### Open questions

- Are maps and events two tabs of one module, or two separate modules in the main navigation bar?

### Ideas

- The list of all events could group each event under its map.
- The main navigation could offer tabs to keep several screens open at once, such as maps or events.

## Create and delete an event

Users create an event from any tile of a map. They can delete each event individually, and deleting a map deletes all the events on it.
